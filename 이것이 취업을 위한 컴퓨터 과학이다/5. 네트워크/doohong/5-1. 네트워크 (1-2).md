# 5장 네트워크
- 네트워크 : 여러 대의 장치가 그물처럼 연결되어 정보를 주고 받는 통신망

## 1. 네트워크의 큰 그림
### 1-1. 네트워크의 기본 구조
- 네트워크 : 노드와 간선으로 이루어진 자료구조로 `그래프` 형태를 띰
  - 기기 : 노드
  - 간선 : 네트워크 기기 간에 정보를 주고 받는 유무선의 통신 매체
![alt text](<네트워크 기본 구조.png>)

- 네트워크 토폴로지 (network topology) : 네트워크 상에서 노드와 노드 사이의 연결 구조 
  - 예 : 망형, 트리형, 링형, 성형, 버스형 
![alt text](<네트워크 토폴로지.png>)

- 호스트 : `네트워크의 가장자리`에 위치하면서 네트워크를 통해 주고 받는 `정보를 최초로 송신하고 최종 수신하는 노드`
  - 흔히 접하는 대부분의 네트워크 기기
  - 예 : 노트북의 웹 브라우저로 구글 홈페이지를 접속한 경우 `노트북`과 `구글의 서버 컴퓨터`가 정보를 주고 받는 과정
      1. 노트북이 구글의 서버 컴퓨터에게 웹 페이지를 가져다 달라는 요청을 보냄
         - 노트북처럼 `요청`을 보내는 호스트를 `클라이언트`라고 함
      2. 구글의 서버 컴퓨터가 노트북에게 웹 페이지로 응답
         - 구글의 서버 컴퓨터처럼 `응답`을 보내는 호스트를 `서버`라고 함

- 클라이언트와 서버는 주고 받는 정보의 방향(요청과 응답)에 따라 부여된 역할
  - 클라이언트 : `요청`을 보내는 호스트
  - 서버 : `응답`을 보내는 호스트
  ![alt text](<클라이언트, 서버 호스트.png>)

- 중간 노드 : 가장자리에 위치한 호스트가 주고 받는 정보들을 원하는 수신지까지 안정적으로 전송하는 역할
  - 중간 노드 역할을 하는 네트워크 장비들 : 스위치, 라우터, 공유기 등

#### 1-1-1. LAN과 WAN
- 네트워크 규모에 따라 LAN과 WAN으로 구분됨
- LAN (Local Area Network) : 근거리 네트워크를 의미하며 가정이나 기업처럼 비교적 가까운 거리를 연결하는 한정된 공간에서의 네트워크를 말함
  - 집이나 사무실에서 있는 공유기를 통해 모든 네트워크 기기가 통신한다면 LAN이 공유기를 기준으로 구촉된 것
    - 이 공유기에 연결된 네트워크 기기들은 모두 같은 네트워크 (LAN)에 속해 있다고 인식함
    - LAN과 다른 LAN끼리 통신도 빈번히 일어남

<br>

- WAN (Wide Area Network) : WAN은인터넷을 가능하게 만드는 네트워크로 LAN 간 통신이 이루어짐 
  - 일반전으로 ISP(Internet Service Provider)라는 인터넷 서비스 업체가 구축하고 관리함
  - 대표적인 국내 ISP : KT, LG U+, SK브로드밴드

#### 1-1-2. 패킷 교환 네트워크
- 패킷 : 네트워크를 통해 송수신되는 데이터의 단위로 `페이로드`와 `헤더`로 구성되어 있으며 `트레일러`라는 정보가 포함됨
  - 페이로드 : 패킷에서 송수신하고자 하는 데이터
  - 헤더 : 패킷에 추가되는 부가 정보
  - 트레일러 : 패킷에 추가되는 부가 정보
- 패킷 교환 네트워크 : 네트워크는 패킷 단위로 주고 받는 정보를 쪼개서 송수신하고 수신지에서 재조립하여 패킷을 주고 받음

#### 1-1-3. 주소의 개념과 전송 방식
- 주소 : 패킷의 `헤더`에 명시되는 정보로 올바르게 정보를 주고 받기 위해 `서로를 특정할 수 있는 정보`
  - 네트워크에서 사용되는 대표적인 주소 : IP, MAC 주소

<br>

- 주소를 바탕으로 다양한 수신지 유형을 지정해 패킷을 보낼 수 있음
  1. 유니캐스트 (unicast)
     - 송신지와 수신지가 일대일로 메시지를 주고 받는 전송 방식
  2. 브로드캐스트 (broadcast)
     - 네트워크 상의 모든 호스트에게 메시지를 전송하는 전송 방식
     - 브로드캐스트 도메인 (broadcast domain) : 브로드캐스트가 전송되는 범위
       - 호스트가 같은 브로드캐스트 도메인에 속해있는 경우 같은 LAN에 속해있는 것
  3. 멀티캐스트 (multicast)
     - 네트워크 내의 동일 그룹에 속한 호스트에게만 전송하는 전송 방식
  4. 애니캐스트 (anycast)
     - 네트워크 내의 동일 그룹에 속한 호스트 중 가장 가까운 호스트에게 전송하는 전송 방식
  ![alt text](<유니캐스트, 브로드캐스트.png>)

### 1-2. 두 호스트가 패킷을 주고 받는 과정
- 호스트가 서로 주고 받는 정보를 이해하기 위한 규칙
  - 프로토콜
  - 네트워크 참조 모델

#### 1-2-1. 프로토콜
- 프로토콜 : 네트워크에서 통신을 주고 받는 노드 간의 합의된 규칙이나 방법
  - 패킷을 주고 받는 호스트와 네트워크 장비들이 서로 주고 받는 정보를 이해하기 위해 같은 프로토콜로 통신해야함
  - 프로토콜 = 네트워크의 언어와 유사

<br>

- 다양한 프로토콜이 있으며 프로토콜마다 `목적`과 `특징`이 다름
- ![!\[alt text\](image.png)](<프로토콜 종류.png>)
  - IP : 네트워크 간의 `주소를 지정`하기 위한 프로토콜 
  - ARP : IP주소와 MAC 주소를 대응시키기 위한 프로토콜 
  - HTTPS : 보안상 HTTP에 비해 `안전`한 프로토콜 
  - TCP : UDP에 비해 `신뢰성`이 높은 프로토콜 

<br>

- 각자 목적과 특징이 다른 프로토콜로 구성되어 `패킷의 내용`도 달라질 수 있음
  - 패킷은 패킷을 구성하는 `프로토콜의 목적과 특징`에 따라 맞는 `패킷 헤더`를 가짐
  - ![!\[alt text\](image.png)](<프로토콜에 따른 패킷 헤더.png>)

#### 1-2-2. 네트워크 참조 모델
- 네트워크 참조 모델 : 네트워크에서 호스트 간 패킷을 주고 받는 정형화된 순서에 따라 `통신이 이루어지는 단계를 계층적으로 표현`한 것
  - 패킷을 `송신`하는 쪽에서는 `상위 계층에서 하위 계층`으로 정보를 보내고 패킷을 `수신`하는 쪽에서는 `하위 계층에서 상위 계층`으로 정보를 받아들임
  - ![alt text](<네트워크 참조 모델.png>)
  - 계층 별로 하는 일이 명확하며 계층별 목적에 맞는 프로토콜 장비를 구성하면 네트워크의 구성, 설계, 문제 진단, 해결이 용이해짐

<br>

- 대표적인 네트워크 참조 모델
1. OSI 모델
   - 국제 표준화 기구 (ISO, International Organization for Standardization)에서 만든 네트워크 참조 모델로 통신 단계를 7개의 계층으로 나눠 OSI 7계층이라고 부름

   1. 물리 계층
      - 최하위 계층으로 비트 신호를 주고 받는 계층
      - 컴퓨터는 0,1만 이해할 수 있기 때문에 네트워크를 통해 주고 받는 정보 또한 0,1로 이루어진 신호
      - 이런 신호를 유무선 통신 매체를 통해 운반하는 계층
   2. 데이터 링크 계층
      - LAN에 속한 호스트끼리 올바르게 정보를 주고 받기 위한 계층
      - 같은 네트워크에 속한 호스트를 식별할 수 있는 주소 (MAC 주소)를 사용함
      - 물리 계층을 통해 주고 받은 정보에 오류가 없는지도 확인
      - 물리 계층과 밀접하게 연관된 계층이며 하드웨어와 밀접하게 맞닿아있음
   3. 네트워크 계층
      - 네트워크 간 통신을 가능하게 하는 계층
      - LAN을 넘어 다른 네트워크와 통신을 주고 받기 위해 필요한 계층
      - 네트워크 간 통신 과정에서 호스트를 식별할 수 있는 주소가 필요
      - 대표적 프로토콜 : IP 주소
   4. 전송 계층
      - 네트워크를 통해 송수신되는 패킷은 전송 도중 유실되거나 순서가 바뀔 수 있음
      - 전송 계층에서 이런 상황에 대비해 신뢰성 있는 전송을 가능하게 함
      - 포트를 통해 특정 응용 프로그램과의 연결 다리 역할을 수행함
      - 대표적인 프로토콜 : TCP, UDP
   5. 세션 계층
      - 응용 프로그램 간 연결 상태를 의미하는 `세션`을 관리하기 위한 계층
      - 응용 프로그램 간의 연결 상태를 유지하거나 새롭게 생성하거나 끊는 역할 
   6. 표현 계층 
      - 번역가와 같은 역할
      - 인코딩, 압축, 암호화와 같은 작업을 수행
      - 세션과 표현 계층은 다른 계층과 달리 명확하게 구분하지 않거나 응용 계층에 포함하여 간주하기도 함
   7. 응용 계층
      - 사용자와 가장 밀접하며 여러 네트워크 서비스를 제공하고 중요한 프로토콜이 다수 포함됨
      - 대표적인 프로토콜 : HTTP, HTTPS, DNS

<br>

2. TCP/IP 모델
- TCP/IP 모델 (TCP/IP 4계층) : `구현과 프로토콜에 중점`을 둔 네트워크 참조 모델
  - 네트워크 액세스 계층, 전송 계층, 응용 계층으로 구성
  - ![alt text](<TCP-IP 모델.png>)
  1. `네트워크 액세스 계층`
    - TCP/IP 모델의 최하위 계층으로 링크 계층, 네트워크 인터페이스 계층이라고도 불림
    - OSI 모델의 데이터 링크 계층과 유사
    - TCP/IP 모델에서는 물리 계층 개념이 없다고 보는 견해도 있음
  2. `인터넷 계층` 
    - TCP/IP 모델의 두번째 계층
    - OSI 모델의 네트워크 계층과 유사
  3. 전송 계층 
     - OSI 모델의 전송 계층과 유사
  4. 응용 계층
     - OSI 모델의 세션 계층, 표현 계층, 응용 계층을 합친 것과 유사

#### 1-2-3. 캡슐화와 역캡슐화

## 2. 물리 계층과 데이터 링크 계층
### 2-1. 이더넷
- 이더넷 : LAN 내의 호스트들이 올바르게 정보를 주고 받을 수 있도록 `통신 매체를 통해 신호를 송수신하는 방법`, `데이터 링크 계층에서 주고 받는 데이터(프레임) 형식` 등이 `정의된 기술`

#### 2-1-1. 이더넷 표준
- 이더넷 : IEEE 802.3이라는 이름으로 국제 표준화된 기술
  - IEEE 802.3은 이더넷과 관련된 다양한 표준들의 모음
  - 서로 다른 제조사의 네트워크 장비라도 LAN 내의 모든 컴퓨터가 문제 없이 호환되기 위해 이더넷 표준을 준수하여 제작됨

<br>

- 이더넷 표준에 대해 유의점
  1. 오늘날의 (유선) LAN 대부분이 이더넷 표준을 따르기 때문에 대다수의 LAN 장비들이 이더넷 표준을 따름
  2. `이더넷 표준`이 달라지면 통신 매체의 종류를 비롯한 `신호 송수신 방법`, 나아가 `최대 지원 속도`도 달라질 수 있음

#### 2-1-2. 이더넷 프레임
- 이더넷 프레임 : 이더넷 기반의 네트워크에서 주고 받는 프레임 
  - 오늘날 주로 사용되는 이더넷 프레임 : Ethernet II 프레임
  - 오늘날 LAN은 대부분 이더넷을 기반으로 구현되기 때문에 사실 상 `프레임`이 `이더넷 프레임`을 지칭한다고 볼 수 있음
  - 프레임은 프리앰블, 수신지 MAC 주소 등의 정보를 포함함
  - ![alt text](<이더넷 프레임.png>)
    1. 프리앰블
       - 송수신지 동기화를 위해 사용되는 8바이트(64비트) 크기의 정보
       - 첫 7바이트는 10101010, 마지막 바이트는 10101011
       - 수신지 입장에서는 프리앰블 비트를 통해 현재 이더넷 프레임이 수신되고 있다는 사실을 알게 됨
    2. 송수신지 MAC 주소 
       - 프레임에서 가장 중요한 정보
       - 송신지와 수신지를 특정할 수 있는 6바이트(48비트) 길이의 MAC 주소 
       - 콜론(:)으로 구분된 12자리 16진수
         - 예 : ab:cd :ab:cd:00:01
       - 물리적 주소로 네트워크 인터페이스마다 하나씩 부여됨 
         - 네트워크 인터페이스 : 네트워크를 향하는 통로로 연결 매체와의 연결 지점
           - 보통 NIC라는 장치가 네트워크 인터페이스를 담당
           - NIC가 여러 개인 경우 네트워크 인터페이스가 여러개이며 한 호스트에 여러개의 MAC 주소를 가질 수 있음
    3. 타입/길이
       - MAC 주소의 타입/길이 필드에 명시된 크기가 1500 이하(16진수 05DC) = 프레임의 크기 
       - MAC 주소의 타입/길이 필드에 명시된 크기가 1536 이상(16진수 0600) = 타입
         - 타입 : 캡슐화된 상위 계층의 정보를 의미 
           - 타입을 통해 어떤 상위 계층 프로토콜이 캡슐화됐는지 알 수 있음 
    4. 데이터
       - 데이터 필드에는 `페이로드`가 명시됨
         - 상위 계층으로 전달하거나 전달받을 데이터가 명시됨
         - 데이터 필드에 포함될 수 있는 데이터의 최대 크기는 정해져있음
           - 최대 : 1500바이트 이하 
             - 이더넷 프레임으로 전송 가능한 최대 데이터 크기
             - 네트워크 계층 패킷 (헤더 + 페이로드)의 최대 크기인 MTU를 지칭하는 데 사용
           - 최대 크기가 넘는 경우 여러 패킷으로 나눠져 보내짐 
    5. FCS (Frame Check Sequence)
       - FCS : 프레임의 오류가 있는지의 여부를 확인하기 위한 필드
         - CRC (Cyclic Redundancy Check)라는 오류 검출용 값이 명시됨
           - 송신지에서 전송할 데이터와 함께 전송할 데이터에 대한 CRC 값을 계산해 보내면 수신지에서 CRC 값을 계산해 전달받은 CRC 값과 대조함 => 같은 경우 프레임에 오류가 없다고 판단

### 2-2. 유무선 통신 매체 
- 네트워크 하드웨어 장비 (통신 매체와 네트워크 장비)
#### 2-2-1. 유선 매체 - 트위스티드 페어 케이블
- 트위스티드 페어 케이블 : 구리선을 통해 전기적으로 신호를 주고 받는 통신 매체 
  - 두 가닥씩 꼬아져 있는 구리선
  - ![!\[alt text\](image.png)](<트위스티드 페어 케이블.png>)

<br>

- 카테고리 : 트위스티드 페어 케이블의 성능을 구분하는 일종의 등급 역할
  - 트위스티드 페어 케이블의 성능을 알 수 있음
  - 카테고리에 따라 대응되는 주요 이더넷 표준, 최대 지원 속도가 달라짐
  - Cat으로 표시함 => 예 : Cat7
  - ![alt text](<Cat 전송속도.png>)

<br>

- 노이즈 : 전기적 신호를 주고 받는 트위트스티드 페어 케이블은 구리선으로  전기 신호에 왜곡을 줄 수 있는 주변 잡음
- 포일 : 노이즈를 방지하기 위해 트위스티드 페어 케이블을 그물 모양의 철사나 포일로 감음
- 차폐 (shielding) : 구리선 주변을 보호해 노이즈를 감소시키는 방식
- 브레이드 실드 (braided shield) 또는 포일 실드 (foil shield) : 차폐에 사용된 그물 모양의 철사나 포일
- STP (Shielded Twisted Pair) 케이블 : 브레이드 실드로 노이즈를 감소시킨 케이블
- FTP (Foil Twisted Pair) 케이블 : 포일 실드로 노이즈를 감소시킨 케이블 
- `UTP` (Unshielded Twisted Pair) : 아무것도 감싸지 않아 구리선만 있는 케이블 

#### 2-2-2. 무선 매체 - 전파와 WIFI
- 전파 : 대표적인 무선 매체로 3kHz부터 3THz 사이의 진동수를 갖는 전자기파
- 와이파이 : 무선 LAN에서 가장 대중적으로 사용되는 기술, IEEE 802.11 표준을 따르는 무선 LAN 기술
  - 이더넷처럼 표준 규격에 따라 지원되는 최대 속도나 주파수 대역 등이 달라질 수 있음
  - ![!\[alt text\](image.png)](<와이파이 규격.png>)
  - 와이파이 주파수 대역
    - 같은 주파수 대역을 사용하는 여러 무선 네트워크가 존재할 수 있음
    - 하지만 전파 통신을 주고 받을 때 주파수 대역이 겹치면 신호 간섭이 발생할 수 있음
      - 서로 같은 주파수 대역을 사용하더라도 신호를 간섭하지 않기 위해 `채널`이라는 하위 주파수 대역을 세분화하여 무선 통신이 이뤄짐
    - ![!\[alt text\](image.png)](<와이파이 주파수 채널.png>)
      - 채널은 자동으로 설정되지만 수동으로 변경 가능

#### 2-2-3. 참고 AP와 SSID
- AP : 여러 무선 통신 기기를 연결해 무선 네트워크를 구성하는 장비
  - 예 : 무선 공유기 
- SSID (Service Set Identifier) : AP를 중심으로 구성된 무선 네트워크인 서비스 셋을 식별하는 식별자
  - 와이파이 이름으로 사용되는 정보가 SSID


### 2-3. 네트워크 인터페이스: NIC 
- 네트워크 인터페이스 : 네트워크 상에서 노드와 통신 매체가 `연결되는 지점`
  - 노드와 네트워크 사이의 통로로 노드가 네트워크를 통해 송수신하는 정보는 네트워크 인터페이스를 거치게 됨
  - 네트워크 인터페이스마다 물리적 주소인 `MAC 주소`가 부여됨

<br>

- NIC (Network Interface Controller) : 네트워크 인터페이스의 역할을 담당하는 하드웨어 
  - 다양한 이름으로 불림
    - 예 : 네트워크 인터페이스 카드, 네트워크 어댑터, LAN 카드, 네트워크 카드, 이더넷 카드 등
  - `통신 매체의 신호`를 `호스트가 이해하는 프레임으로 변환`하거나 `호스트가 이해하는 프레임을 통신 매체의 신호로 변환`하는 역할을 수행
  - MAC 주소를 토대로 `잘못 전송된 패킷이 없는지 확인`도 해줌
  - 확장 카드 형태의 장비였지만 최근에는 USB 연결이나 메인 보드 내장 등 다양한 형태로 변화
  - NIC도 입출력장의 일종
    - 출력 : 패킷을 송신하는 동작
    - 입력 : 패킷을 수신하는 동작
    - NIC를 작동시키는 시스템 콜이 호출되면 커널 모드로 전환된 후 송수신이 수행되고 입출력이 완료되면 인터럽트를 통해 CPU에게 작업이 완료됐음을 알림
    - ![!\[alt text\](image.png)](<NIC 동작.png>)
  - NIC의 지원 속도가 종류마다 다르고 네트워크 속도에 영향을 미침
    - 고대역폭을 감당해야한다면 메인보드에 내장된 NIC있어도 고속 NIC를 추가로 구비하기도 함

  - ![!\[alt text\](image.png)](허브.png)

<br>

- 허브의 중요한 2가지 특징
1. 전달받은 신호를 모든 포트로 내보냄
   - 허브는 신호를 받으면 조작이나 판단을 하지 않고 단순히 모든 포트에 신호를 내보냄
2. 반이중 모드로 통신
   - 반이중 모드 : 송신 또는 수신을 번갈아 가면서 수행해야 하는 통신 방식
     - 동시 송수신이 불가능한 상태
     - 만일 허브를 향해 동시에 메시지를 보내면 충돌이 생김
     - 허브가 전달 받은 모든 포트로 내보내는 동시에 반이중 모드로 통신하기 때문에 연결된 모든 호스트는 충돌이 발생할 수 있는 영역인 `콜리전 도메인`이 됨
     - ![!\[alt text\](image.png)](<컬리전 도메인.png>)
   - 전이중 통신 : 동시 송수신이 가능한 상태, 전화처럼 양방향 송수신이 가능함
     - 데이터 링크 계층의 네트워크 장비인 스위치는 전이중 모드

#### 2-4-2. 데이터 링크 계층의 스위치
- 스위치 : 허브의 한계를 보완하기 위한 네트워크 장비로 `전달받은 신호를 목적지 호스트가 연결된 포트로만 내보내고 전이중 모드를 지원`하여 콜리전 도메인이 좁음
  - ![!\[alt text\](image.png)](스위치.png)
  - MAC 주소 학습을 통해 스위치는 전달받은 신호를 원하는 포트에만 내보낼 수 있음
  - 스위치는 데이터 링크 계층에 속해있어 MAC 주소를 이해할 수 있음

<br>

- MAC 주소 테이블 :  프레임 속 MAC 주소를 토대로 현재 어떤 포트에 어떤 MAC 주소를 가진 호스트가 연결되었는지 파악하고 포트와 MAC 주소의 대응 관계를 테이블의 메모리에 저장함
- ![!\[alt text\](image.png)](<MAC 주소 테이블.png>)

<br>

- VLAN (Virtual LAN) : 스위치의 대표 기능 중 하나로 가상의 LAN
  - 같은 스위치에 연결된 모든 호스트를 하나의 네트워크로 간주하는 게 아니라 여러 논리적인 네트워크로 나눔
  - 논리적으로 다른 네트워크로 나눈 경우 서로 통신을 주고 받으려면 네트워크 계층 이상의 장비가 필요
  - ![!\[alt text\](image.png)](VLAN.png)


## Q&A 
### Q1. 네트워크 참조 모델에 대해서 순서를 포함하여 설명하세요.
A1. 네트워크 참조 모델은 네트워크에서 호스트 간 패킷을 주고 받는 정형화된 순서에 따라 통신이 이루어지는 단계를 계층적으로 표현한 것입니다.

패킷을 송신하는 쪽에서는 상위 계층에서 하위 계층으로 정보를 보내고 패킷을 수신하는 쪽에서는 하위 계층에서 상위 계층으로 정보를 받아들입니다.

대표적인 네트워크 참조 모델로는 OSI 모델과 TCP/IP 모델이 있습니다. OSI 모델은 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층으로 이루어져있습니다.

TCP/IP 모델은 네트워크 액세스 계층, 전송 계층, 응용 계층으로 구성되어 있습니다.

### Q2. OSI 7계층의 각 단계를 순서대로 설명하세요.
A2. OSI 7 계층은 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층으로 이루어져있습니다.

물리 계층은 최하위 계층으로 비트를 통한 신호를 유무선 통신 매체를 통해 운반하는 계층입니다.
데이터 링크 계층은 LAN에 속한 호스트끼리 올바르게 정보를 주고 받기 위한 계층으로 MAC 주소를 통해 호스트를 식별하며 정보에 오류가 없는지 확인합니다.
네트워크 계층은 LAN을 넘어 다른 네트워크와 통신을 주고 받기 위해 필요한 계층이며 네트워크 간 통신과정에서 호스트를 식별하기 위해 IP 주소를 사용합니다.
전송 계층은 포트를 통해 응용 프로그램과의 연결 다리 역할을 수행하며 송수신된 패킷의 정보나 순서를 신뢰성 있게 전송하게 합니다.
세션 계층은 응용 프로그램 간 연결 상태를 유지하거나 새롭게 생성하거나 끊는 역할을 합니다.
표현 계층은 인코딩, 압축, 암호화 역할을 수행합니다.
응용 계층은 사용자와 가장 밀접하며 여러 네트워크 서비스를 제공합니다.

### Q3. 이더넷이 무엇인가요?
A3. 이더넷은 서로 다른 제조사의 네트워크 장비라도 모든 컴퓨터가 문제 없이 호환되기 위한 국제 표준화된 기술입니다. 이더넷 기반의 네트워크에서 주고 받는 프레임을 이더넷 프레임이라고 부르며 송수신지 동기화를 위해 사용되는 프리앰블, 송수신지 MAC 주소, 타입/길이, 데이터, CRC 값을 통해 오류를 검출하는 FCS 필드를 가집니다.
