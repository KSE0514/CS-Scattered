# 05-3. 네트워크 계층 - IP

## IP의 목적과 특징

- IP의 목적 : 주소 지정, 단편화
- IP의 특징 : 신뢰할 수 없는 통신, 비연결형 통신

### 주소 지정과 단편화

- **주소 지정(addressing)** : 네트워크 간의 통신 과정에서 호스트를 특정하는 것
    - IP 주소 통해 이루어짐
    - IPv4 패킷 헤더 - 송수신지 IP 주소 : 송수신지를 식별할 수 있는 IP 주소 명시
        - **하나의 IP 주소** : 0~255 범위의 10진수 4개(4바이트)로 표기
            - **옥텟(octet)** : 점(.)으로 구분된 하나의 10진수 → 4개의 옥텟
            - 192.168.0.1 ⇒ 192, 168, 0, 1이 각각 8비트로 표현 가능한 옥텟
                
                ![IP 패킷 헤더와 페이로드(일부)](image%2026.png)
                
                IP 패킷 헤더와 페이로드(일부)
                
    - MAC 주소와의 비교
        - MAC 주소 : 수신인, 발신인
        - IP 주소 : 수신 주소, 발신 주소
        - 패킷을 올바르게 전송하기 위해 모두 필요, 송수신 과정에 IP 주소 우선적 활용
    - **라우터(router)** : IP 주소를 바탕으로 목적지까지 IP 패킷 전달하는 네트워크 장비
        - **라우팅(routing)** : IP 패킷을 전달할 최적의 경로를 결정하고 해당 경로로 패킷을 내보내는 과정
    - 참고 - IPv6
        - 하나의 IPv4 주소는 총 32비트로 총 2^32개(약 42억 개)개의 주소 할당 가능 ⇒ 고갈될 여지 있음
        - IPv6은 16바이트(128비트)로 총 2^128개의 주소 할당 가능
            - 콜론(:)으로 구분된 8개의 그룹의 16진수로 표기
            - 2001 : 0230 : abcd : ffff : 0000 : 0000 : ffff : 1111
        - 오늘날 더 빈번히 사용하는 IP는 IPv4
- **단편화(fragmentation)** : 데이터를 여러 IP 패킷으로 올바르게 쪼개어 보내는 것
    - **MTU(Maximum Transmission Unit)** : 최대 전송 단위
        - IP 패킷의 크기가 MTU 보다 클 경우 패킷을 MTU 이하의 여러 패킷으로 쪼개어 전송, 수신지에서 재조합
        - 일반 크기 1500바이트 → 프레임을 통해 주고받을 수 있는 최대 페이로드의 크기
    - 단편화와 관련된 필드
        
        ![image.png](image%2027.png)
        
        - **식별자(identifier)**
            - 특정 패킷이 어떤 데이터에서 쪼개진 패킷인지 식별하기 위해 사용되는 필드
            - 같은 정보에서 쪼개진 패킷들은 같은 식별자를 공유하기 때문에 식별자를 통해 단편화되어 전송되는 패킷 구분 가능
        - **플래그(flag)** - 3비트
            - 첫 번째 비트 : 항상 0, 오늘날 사용되지 않음
            - 두 번째 비트 : DF(Don`t Fragment) - IP 단편화를 수행하지 말라
            - 세 번째 비트 : MF(More Fragment) - 단편화된 패킷이 더 있다
                
                ![image.png](image%2028.png)
                
        - **단편화 오프셋(fragement offset)**
            - 특정 패킷이 초기 데이터에서 얼마나 떨어져 있는지 명시된 필드
            - 단편화되어 전송되는 패킷을 목적지에서 재조합하기 위해 패킷의 올바른 순서를 나타내는데 사용
    - 오늘날 네트워크 환경에서는 IP 단편화가 잘 발생하지 않음
        - 대부분 경로 MTU 발견 지원 및 처리 가능한 최대 MTU 크기 균일
        - **IP 단편화가 자주 발생하면?**
            - 단편화된 패킷이 많아지고 그만큼 전송해야 할 패킷 헤더가 많아짐 → 불필요한 트래픽 증가, 대역폭 낭비 초래
            - 단편화된 패킷 재조립하는 과정에서 발생하는 부하 → 성능 저하로 이어질 수 있음
        - **IP 단편화 피하려면?**
            - **경로 MTU** : IP 패킷을 주고받는 경로에 존재하는 모든 호스트의 처리 가능한 MTU 크기
            - **경로 MTU 발견** : 주고받을 수 있는 경로 MTU를 구하고 해당 크기만큼만 송수신하여 IP 단편화를 회피하는 기술

### 신뢰할 수 없는 통신과 비연결형 통신

- **신뢰할 수 없는 프로토콜(unreliable procotol)** : 패킷이 수신지까지 제대로 전송되었다고 보장하지 않는 프로토콜
    - 패킷이 유실되거나 목적지에 순서대로 전송되지 않더라도 조치 취하지 않음
    - **신뢰성이 낮은 통신/최선형 전달(best effort delivery)** : 신뢰할 수 없는 프로토콜의 송수신
- **비연결형 프로토콜(connectionless protocol)** : 패킷을 주고받기 전에 사전 연결 과정을 거치지 않음
    - 상대 호스트의 수신 가능 여부를 고려하지 않고 수신지를 향해 패킷 전송
    - ↔ **TCP** : 송수신지 간의 연결 설정을 통해 패킷을 주고받을 호스트 간에 송수신 준비가 되었는지 확인 가능

## IP 주소 구조

IP 주소 = 네트워크 주소 + 호스트 주소

- **네트워크 주소** : 호스트가 속한 네트워크를 특정하기 위해 사용
    - (= 네트워크 ID, 네트워크 식별자)
- **호스트 주소** : 네트워크에 속한 호스트를 특정하기 위해 사용
    - (= 호스트 ID, 호스트 식별자)

### 클래스풀 주소 체계

네트워크 주소 크기와 호스트 주소 크기는 유동적

- **클래스풀 주소 체계** : 클래스를 바탕으로 IP 주소를 관리하는 주소 체계
- **클래스(class)** : 네트워크 크기에 따라 유형별로 IP 주소를 분류하는 기준
    - A, B, C - 네트워크 크기별로 IP 주소를 분류하는데 실질적으로 사용되는 클래스
        - A (0.0.0.0 ~ 127.255.255.255)
            - 네트워크 주소 - 비트 0으로 시작, 1옥텟
            - 호스트 주소 - 3 옥텟
            - 상대적으로 가장 많은 호스트를 할당할 수 있는 클래스
        - B (128.0.0.0 ~ 191.255.255.255)
            - 네트워크 주소 - 비트 10으로 시작, 2옥텟
            - 호스트 주소 - 2옥텟
        - C (192.0.0.0 ~ 223.255.255.255)
            - 네트워크 주소 - 비트 110으로 시작, 3옥텟
            - 호스트 주소 - 1옥텟
        
        ![image.png](image%2032.png)
        
    - D, E - 멀티캐스트를 위한 클래스
- 참고 - 네트워크/브로드캐스트 주소와 예약 주소
    - 호스트의 주소 공간을 모두 사용할 수 있는 것은 아님
        - 호스트 주소가 전부 0 - 해당 네트워크 자체를 의미하는 주소
        - 호스트 주소가 전부 1(255) - 브로드캐스트를 위한 주소
    - 예약 IP 주소
        
        ![image.png](image%2033.png)
        
        - **이 네트워크의 이 호스트** : 0.0.0.0, 가장 일반적으로 사용, 호스트가 IP 주소를 할당 받기 전 임시로 사용하거나 마땅히 자신을 지칭할 IP 주소 없을 때 사용
        - **루프백 주소(loopback address)** : 자기 자신을 가리키는 특별한 주소
            - **로컬호스트(localhost)** : 127.0.0.1, 가장 일반적으로 사용되는 루프백 주소
            - 루프백 주소로 전송된 패킷은 자기 자신에게 되돌아오므로 자기 자신을 다른 호스트인 것처럼 간주하여 패킷 전송 가능
        - **사설 네트워크 주소** : 사설 네트워크에서 사용하기 위한 IP 주소

## 클래스리스 주소 체계와 서브넷 마스크

- **클래스리스 주소 체계(classless addressing)** : 클래스를 이용하지 않고 네트워크와 호스트를 구분하는 방식
    - 클래스풀 주소 체계의 한계를 보완하기 위해 등장
        - 네트워크 크기가 고정되어 있으면 고정된 크기 이외에 다른 크기의 네트워크를 구성할 수 없어 IP 주소가 낭비될 수 있음
        - 더 정교하고 유동적으로 네트워크 영역을 나눌 수단 필요
- **서브넷 마스크(subnet mask)**
    - IP 주소상에서 네트워크 주소를 1, 호스트 주소를 0으로 구분하여 표기한 비트열
    - **서브네트워크(subnetwork)/서브넷(subnet)** : IP 주소에서 네트워크 주소로 구분할 수 있는 네트워크의 부분집합
    - **서브네팅(subnetting)** : 서브넷 마스크를 이용해 원하는 크기로 클래스를 더 잘게 쪼개어 사용하는 것
    - IP 주소 내의 네트워크 주소 구하는 방법
        - 서브넷 마스크와 IP 주소 간 비트 AND 연산 수행
            - 비트 AND 연산 : A, B 값이 둘 다 1이어야 연산의 결과 1
                
                ![image.png](image%2034.png)
                
            
            ![image.png](image%2035.png)
            
    - **CIDR 표기(Classless Inter-Domain Routing notiation)** - 서브넷 마스크 표기법
        - IP 주소/서브넷 마스크상의 1의 개수 형식으로 표기
        - 192.168.20.3**/30** ⇒ 서브넷 마스크 : 11111111.11111111.11111111.11111100(= 255.255.255.252)

## 공인 IP 주소와 사설 IP 주소

호스트의 IP 주소 확인하는 법 : 네트워크 설정이나 명령어 통해 / 간단한 온라인 검색 통해

- 윈도우 - ‘ipconfig/all’
- 맥OS, 리눅스 - ‘ifconfig’
    
    

**고유성에 따른 IP 주소 종류**

- **공인 IP 주소** : 전 세계에서 고유한 IP 주소
    - 인터넷을 비롯한 네트워크 간 통신에서 사용되는 IP 주소
    - ISP나 공인 IP 주소 할당 기관을 통해 할당받을 수 있음
- **사설 IP 주소** : 사설 네트워크에서 사용하기 위한 IP 주소
    - **사설 네크워크** : 외부 네트워크에 공개되지 않은 네트워크
        - 사설 IP 주소는 해당 호스트가 속한 사설 네트워크 상에서만 유효해 다른 네트워크 상의 사설 IP 주소와 중복될 수 있음
    - 일반적으로 라우터를 통해 할당
    - 사설 IP 주소 범위
        - 10.0.0.0/8 (10.0.0.0 ~ 10.255.255.255)
        - 172.16.0.0/12 (172.16.0.0~172.31.255.255)
        - 192.168.0.0/16 (192.168.0.0~ 192.168.255.255)

## IP 주소의 할당

### 정적 할당

직접 수작업으로 IP 주소를 부여하는 방식

- **정적 IP 주소(static IP address)** : 정적 할당을 통해 할당된 IP 주소
- 정적 IP 주소를 부여하기 위해 필요한 값
    - 정적 IP를 부여하고자 하는 IP 주소, 서브넷 마스크, 게이트웨이 (라우터) 주소, DNS 주소 등
    - **게이트웨이(gateway)** : 서로 다른 네트워크를 연결하는 하드웨어적/소프트웨어적 수단
        - **기본 게이트웨이(default gateway)** : 호스트가 속한 네트워크의 외부로 나가기 위한 첫 기본 경로 ⇒ 라우터의 주소를 의미하는 경우 많음
        - 게이트웨이 주소 = 라우터의 주소
    - **DNS 주소** : 호스트가 도메인 네임을 토대로 IP 주소를 알아내기 위해 질의하는 서버의 주소
        - **도메인 네임** : IP 주소에 대응되는 기억할 수 있는 문자열, 호스트 식별 가능
        - **DNS 서버(네임 서버)** : <도메인 네임, IP 주소> 쌍을 저장하는 서버
            - 호스트가 도메인 네임을 토대로 대응되는 IP 주소를 알아내기 위해 DNS 서버에 질의
            

### 동적 할당 : DHCP

프로토콜을 통해 자동으로 IP 주소를 부여하는 방식

- **동적 IP 주소(dynamic IP address)** : 동적 할당을 통해 할당된 IP 주소
- **DHCP(Dynamic Host Configuration Protocol)**
    - 호스트는 DHCP 서버와의 메시지를 주고받으며 동적 IP 주소를 할당 받을 수 있음
    - **DHCP 서버** : 호스트에 할당 가능한 IP 주소 목록을 관리하다가 IP 주소 할당 요청을 받았을 때 IP 주소를 할당해 주는 호스트
        - 라우터가 DHCP 서버 역할 수행
- ✨**동적 IP 주소 특징**
    - 동적 IP 주소에는 사용 가능한 기간(임대 기간)이 정해져 있음
        - 사용되지 않을 경우 회수
        - 사용 기간이 끝나면 DHCP 서버로 IP 주소 반납
        - **임대 갱신** : IP 주소의 임대 기간이 끝나기 전에 임대 기간을 연장하는 것
            - 자동으로 두 차례 수행, 두 번 모두 갱신 실패하면 IP 주소 반납
    - 동적 IP 주소는 할당 받을 때마다 다른 주소를 받을 수 있음

## IP 전송 특징의 보완 : ICMP

IP의 특징(신뢰할 수 없는 비연결형 통신)은 반드시 극복해야하는가? **No!**

- 신뢰성 높은 연결형 송수신을 하려면 패킷에 대한 오류 제어와 패킷을 주고받는 호스트 간 연결 수립 및 관리를 해야 함
- 패킷의 빠른 송수신과 배치되는 작업으로 더 많은 시간, 대역폭, 부하 필요 ⇒ 성능 상 불리하게 작용할 수 있음

**IP 전송 특징을 보완하기 위한 방법**

1. 신뢰할 수 있는 연결형 통신을 지원하는 상위 계층의 프로토콜 이용 ⇒ TCP
2. 네트워크 계층의 프로토콜인 ICMP 이용
- **ICMP(Internet Control Message Protocol)** : IP 패킷의 전송 과정에 대한 피드백 메시지(ICMP 메시지)를 얻기 위해 사용하는 프로토콜
    - ICMP 메시지를 통해 패킷이 상대방에게 어떻게 전송되었는지 알 수 있음
        
        ![image.png](image%2036.png)
        
        ① 오류 보고
        
        - **네트워크 도달 불가** : 네트워크 장비가 패킷을 전달 받았는데, 해당 패킷을 어떤 네트워크로 전송해야 할 지 알 수 없을 경우
        - **단편화가 필요하지만 DF가 1로 설정되어 단편화할 수 없음** : 처리하기에 너무 큰 패킷을 전달 받았는데, DF 플래그가 설정되어 있어 단편화가 불가능한 경우
        - **시간 초과**
            - **TTL(Time To Live)** : IP 헤더 필드 중 패킷의 수명 의미(무의미한 패킷이 네트워크 상에 지속적으로 남아있는 것을 방지하기 위해)
            - 패킷은 멀리 떨어진 호스트끼리 통신할 때 여러 라우터를 거쳐 이동할 수 있는데, 하나의 라우터를 거칠 때(홉, hop)마다 TTL이 1씩 감소
            - TTL 필드가 0이 되면 해당 패킷 폐기, 패킷을 송신한 호스트에게 메시지 전송

        ② 네트워크 상의 간단한 문제 진단 및 테스트
        
        - traceroute(윈도우 - tracert) - 네트워크 상의 경로를 확인하는 명령어
        - ping - 네트워크 상태를 점검하기 위해 패킷을 송신하는 명령어(ICMP 기반으로 구현된 대표적인 명령어)

    - ICMP가 IP의 신뢰성을 완전히 보장하지 않음 ⇒ 전송 계층의 프로토콜 필요

## IP 주소와 MAC 주소의 대응 : ARP

**ARP(Address Resolution Protocol)** : IP 주소와 MAC 주소를 함께 활용하는 통신 과정에서 동일 네트워크 내에 있는 송수신 대상의 IP 주소를 통해 MAC 주소를 알아내는 프로토콜

**ARP의 동작 과정 - ARP 요청 메시지와 ARP 응답 메시지**

- ARP 요청 메시지
    - 브로드캐스트 메시지(네트워크 내에 있는 모든 호스트에게 보내는 메시지)
    - 알고 싶은 MAC 주소에 대응되는 IP 주소 포함
        
        ![image.png](image%2039.png)
        
- ARP 응답 메시지
    - 네트워크 내의 모든 호스트가 메시지를 수신하여 IP 주소가 자신과 관련이 없으면 무시, 자신의 IP 주소일 경우 ARP 응답 메시지 전송
    - 응답 메시지를 보내는 호스트의 MAC 주소 포함
    - ARP 요청 메시지를 보낸 호스트가 이 응답 메시지를 수신하면 IP 주소를 통해 MAC 주소 알아낼 수 있음
        
        ![image.png](image%2040.png)
        
- 호스트는 ARP 테이블 정보 유지
    - 나중에 같은 호스트에게 패킷을 보낼 때 브로드캐스트 메시지를 보내지 않기 위해
    - **ARP 테이블** : <IP 주소, MAC 주소>의 항목들로 구성된 표 형태의 정보
        - ARP 요청 메시지와 ARP 응답 메시지를 통해 알게 된 주소 쌍을 ARP 테이블에 추가
        - ARP 테이블 항목은 일정 기간 지나면 삭제, 임의로 삭제 가능
        - 윈도우 명령 프롬프트(CMD), 맥OS/리눅스 터미널 - ‘arp -a’ 입력하여 확인

# Q&A
## 1. IP의 목적과 특징은 무엇인가요?
IP의 목적은 주소 지정과 단편화입니다.  
주소 지정은 네트워크 간 통신 과정에서 호스트를 특정하는 것으로 IP 주소를 통해 이루어집니다. 하나의 IP 주소는 4개의 옥텟으로 표기됩니다.  
단편화는 데이터를 여러 IP 패킷으로 올바르게 쪼개어 보내는 것으로 패킷의 크기가 MTU보다 클 경우 MTU 이하의 여러 패킷으로 쪼개어 전송하게 됩니다.  
IP의 특징은 신뢰할 수 없는 비연결형 프로토콜이라는 점입니다.  
패킷이 수신지까지 제대로 전송되었다고 보장하지 않고, 패킷을 주고 받기 전까지 사전에 연결 과정을 거치지 않습니다.


## 2. 클래스풀 주소 체계와 클래스리스 주소 체계의 차이점을 설명해주세요.
클래스풀 주소 체계는 네트워크의 크기에 따라 유형별로 IP 주소를 분류하는 기준인 클래스를 바탕으로 IP 주소를 관리하는 주소 체계입니다.  
클래스는 총 5개로 구분되며 각 클래스마다다 네트워크 크기가 고정되어 있습니다. 그 크기 이외의 다른 크기의 네트워크를 구성할 수 없어 IP 주소가 낭비될 수 있다는 단점이 있습니다.  
반면, 클래스리스 주소 체계는 서브넷 마스크를 이용해 네트워크와 호스트를 구분하는 방식입니다.
서브넷 마스크는 네트워크 주소를 1, 호스트 주소를 0으로 표기한 비트열로, 이러한 서비넷 마스크를 이용해 클래스를 원하는 크기로 더 잘게 쪼개어 사용할 수 있습니다.  
따라서 클래스리스 주소 체계는 클래스를 사용하지 않아 클래스풀 주소 체계보다 더 정교하고 유동적으로 네트워크 영역을 나눌 수 있다는 점에서 차이점이 있있습니다.  


## 3. 동적 IP 주소의 특징을 설명해주세요.
동적 IP 주소의 특징은 2가지가 있습니다.  
첫 번째는 임대 기간이 정해져있다는 것입니다.  
동적 IP 주소가 사용되지 않을 경우 회수하고, 사용 기간이 끝나면 DHCP 서버로 IP 주소를 반납합니다. 또한 IP 주소의 임대 기간이 끝나기 전에 연장하는 임대 갱신을 할 수도 있습니다.  
두 번째는 동적 IP 주소는 할당 받을 때마다 다른 주소를 받을 수 있다는 것입니다.  
프로토콜을 통해 자동으로 IP 주소를 부여하기 때문입니다.
