# 02-4. 메모리

## RAM

- **Random Access Memory** : 임의의 접근 메모리
  - **임의 접근** : 임의의 위치에 곧장 접근 가능한 방식 (= 직접 접근)
    - 어떤 데이터든 접근 시간이 동일함
  - **순차 접근** : 특정 위치에 저장된 요소에 접근하기 위해 처음부터 접근 (임의 접근과 반대)

**특징**

- **휘발성 저장장치** : 전원을 끄면 저장하고 있던 데이터와 명령어 날아감
  - 비휘발성 저장장치와 대조(보조기억장치)
- RAM의 용량은 컴퓨터 성능에 영향 미침
  - RAM이 크면 보조기억장치로부터 많은 데이터를 가져와 미리 저장 ⇒ 많은 프로그램 동시 실행 유리
  - RAM의 용량과 컴퓨터의 성능은 반드시 비례하진 않음

### RAM의 종류

1. **DRAM(Dynamic RAM)**
   - 시간이 지나면 저장된 데이터가 점차 사라지는 RAM
   - 데이터 소멸 막기 위해 일정 주기로 데이터 재활성화
   - 소비 전력 낮음, 저렴, 집적도 높음 ⇒ 메모리 대용량 설계 용이 ⇒ 일반적으로 사용
2. **SRAM(Static RAM)**
   - 시간이 지나도 저장된 데이터가 사라지지 않는 RAM
     - 전원이 공급되지 않으면 저장된 내용 소실됨 ⇒ 비휘발성은 아님
   - DRAM에 비해 속도는 빠르나 소비 전력 크고, 비싸고, 집적도 낮음 ⇒ 캐시 메모리 등 (대용량으로 만들 필요 없고 속도가 빨라야 하는 저장장치)
3. **SDRAM(Synchronous Dynamic RAM)**
   - 클럭 신호와 동기화된 DRAM
     - 클럭 타이밍에 맞춰(한 클럭당 한 번씩) CPU와 정보 주고 받을 수 있음 (= SDR SDRAM)
4. **DDR SDRAM(Double Data Rate SDRAM)**
   - 두 배로 대역폭을 넓혀 속도를 빠르게 만든 SDRAM
     - **대역폭** : 데이터를 주고받을 길의 너비
     - SDRAM보다 전송 속도 두 배 가량 빠름
   - DDR2 SDRAM : DDR SDRAM보다 대역폭이 두 배 넓은 SDRAM
   - DDR3 SDRAM : DDR2 SDRAM보다 대역폭이 두 배 넓은 SDRAM
   - DDR4 SDRAM : SDRAM보다 대역폭이 열여섯 배 넓은 SDRAM

## 메모리에 바이트를 밀어 넣는 순서 - 빅 엔디안과 리틀 엔디안

메모리는 CPU로부터 데이터를 **워드 단위**(32비트(4바이트), 64비트(8바이트))로 받아들여 여러 **바이트**로 구성된 데이터를 여러 주소에 걸쳐 저장

**메모리에 바이트를 저장하는 방식 - 연속해서 저장해야 하는 바이트를 어떤 순서로 저장하느냐**

- **빅 엔디안(big endian)** : 낮은 번지의 주소에 상위 바이트(가장 큰 값)부터 저장하는 방식
  - **MSB(Most Significant Bit)** : 숫자의 크기에 가장 큰 영향을 미치는 유효 숫자
  - 메모리 값을 직접 읽거나 디버깅 할 때 편리
    - 숫자 체계를 읽고 쓰는 순서와 동일 → 1A, 2D, 3C ⇒ 1A2D3C  
  ![image.png](image%2021.png)
- **리틀 엔디안(little endian)** : 낮은 번지의 주소에 하위 바이트부터 저장하는 방식
  - **LSB(Least Significant Bit)** : 숫자의 크기에 가장 적은 영향을 미치는 유효 숫자
  - 수치 계산 편리
    - 123 + 456 → 일의 자리부터 더하기  
  ![image.png](image%2022.png)
- **바이 엔디안(bi-endian)** : 컴퓨터 환경에서 빅 엔디언과 리틀 엔디언 중 하나를 선택
  ```python
  import sys
  print(sys.byteorder) # big - 빅 엔디안, little - 리틀 엔디안 환경

  import struct
  print(struct.pack('>f', 107.6640625).hex()) # 42d75400
  print(struct.pack('<f', 107.6640625).hex()) # 0054d742

  '''
  빅 엔디안(>) 방식으로 표기된 소수(f)를 16진수(hex)로 표현하라
  리틀 엔디안(<) 방식으로 표기된 소수(f)를 16진수(hex)로 표현하라
  '''
  ```

## 캐시 메모리

**CPU와 메모리 사이**에 위치한 **SRAM** 기반의 저장장치

- CPU의 연산 속도와 메모리 접근 속도의 차이를 줄이기 위한 저장장치
- CPU가 **메모리에 접근** 하는 속도 **<** CPU가 **레지스터에 접근**하는 속도
- CPU가 사용할 일부 데이터를 미리 캐시 메모리로 가져와 활용  
  ![image.png](image%2023.png)

**캐시 메모리 종류**

- 코어와 가장 가까운 캐시 메모리 순서대로 : L1, L2, L3
  - 코어 내부 : L1, L2
  - 코어 외부 : L3
- 특징
  - 크기 : L1 < L2 < L3
  - 속도 : L3 < L2 < L1
  - CPU가 메모리 내에 데이터가 필요하다고 판단하면 L1, L2, L3 순서대로 해당 데이터가 있는지 검색
  - 멀티코어 프로세서에서의 구현
    - L1, L2 - 코어마다 고유한 캐시 메모리로 할당
    - L3 - 여러 코어가 공유하는 형태
  - 분리형 캐시
    - L1I 캐시 - 명령어만 저장
    - L1D 캐시 - 데이터만 저장  
      ![image.png](image%2024.png)

### **캐시 히트와 캐시 미스**

- **캐시 히트** : 캐시 메모리가 예측하여 저장한 데이터가 CPU에 의해 실제로 사용되는 경우
- **캐시 미스** : 자주 사용될 것으로 예측하여 캐시 메모리에 저장했지만 틀린 예측으로 인해 CPU가 메모리로부터 필요한 데이터를 직접 가져와야 하는 경우
  - 캐시 히트에 비해 CPU 성능 떨어짐
- **캐시 적중률** : 캐시가 히트되는 비율
  - 캐시 히트 횟수 / (캐시 히트 횟수 + 캐시 미스 횟수)

## RAID

**데이터의 안전성 혹은 성능을 확보**하기 위해 여러 개의 독립적인 보조기억장치를 **하나의 보조기억장치처럼 사용**하는 기술

### RAID0

데이터를 여러 보조기억장치에 단순하게 나누어 저장하는 구성 방식

- **스트라입** : 줄무늬처럼 분산되어 저장된 데이터
- **스트라이핑** : 분산하여 저장하느나 동작  
  ![image.png](image%2030.png)
- 빠른 입출력 속도
- 저장된 정보가 안전하지 않음 → 하나에 문제 생기면 다른 곳에 저장된 데이터는 불완전

### RAID1

완전한 복사본을 만들어 저장하는 구성 방식(= 미러링)  
    ![image.png](image%2031.png)

- 간단한 복구, 높은 안전성
- 데이터를 쓸 때 원본과 복사본 두 곳에 써야 함 → 쓰기 속도 느려짐
- 복사본이 저장된 크기만큼 사용 가능한 용량이 적어짐

### RAID4

패리티 정보를 저장하는 디스크를 따로 두는 구성 방식

- **✨패리티** : 오류를 검출할 수 있는 정보  
  ![image.png](image%2032.png)
- 적은 하드 디스크로도 높은 안전성
- 패리티 저장하는 장치에 병목 현상 발생
  - 데이터가 저장될 때마다 패리티를 저장하는 디스크에도 데이터를 써야하기 때문

### RAID5

패리티를 분산하여 저장하는 구성 방식  

![image.png](image%2033.png)

- 병목 현상 보완

### RAID6

서로 다른 2개의 패리티를 두는 구성 방식  

![image.png](image%2034.png)

- 새로운 정보 저장할 때마다 함께 저장할 패리티가 2개로, RAID5에 비해 쓰기 속도 느림

## 입출력 기법

### 장치 컨트롤러와 장치 드라이버

- **장치 컨트롤러** : CPU와 입출력장치 사이의 통신을 중개
  - RAM과 같은 저장장치가 있어 정보를 주고 받는 과정에서 중간 값들이 저장됨
- **장치 드라이버** : 장치 컨트롤러의 동작을 알고, 장치 컨트롤러가 컴퓨터 내부와 정보를 주고받을 수 있도록 하는 프로그램

### 프로그램 입출력

프로그램 속 명령어로 입출력을 수행하는 방법

- **고립형 입출력(isolated I/O)**
  - 입출력장치에 접근하는 주소와 메모리에 접근하는 주소를 별도의 주소 공간으로 간주하는 방식
  - 별도의 입출력 명령어 필요
- **메모리 맵 입출력(memory mapped I/O)**
  - 입출력장치에 접근하는 주소 공간과 메모리에 접근하는 주소 공간을 구분하지 않고 메모리에 부여된 주소 공간 일부를 입출력장치를 식별하기 위한 주소 공간으로 사용하는 방식  
    ![image.png](image%2036.png)

### 인터럽트 기반 입출력 : 다중 인터럽트  

![image.png](image%2037.png)

왼쪽 : 플래그 레지스터 속 인터럽트를 비활성화한 채 인터럽트 처리할 경우 ⇒ **다른 하드웨어 인터럽트를 받아들이지 않음** / 인터럽트 우선순위가 순서대로인 경우

오른쪽 : 플래그 레지스터 속 인터럽트 비트가 활성화되어 있는 경우/ 인터럽트 비트를 비활성화해도 무시할 수 없는 인터럽트(NMI)가 발생한 경우 ⇒ **우선순위가 더 높은 인터럽트부터 처리**

**프로그래머블 인터럽트 컨트롤러(PIC) :** 여러 장치 컨트롤러에 연결되어 있어 장치 컨트롤러에서 보낸 하드웨어 인터럽트 요청들의 우선순위를 판별한 뒤, CPU에게 지금 처리해야 할 하드웨어 인터럽트가 무엇인지 알려주는 장치  

![image.png](image%2038.png)

- NMI까지 우선순위를 판별하진 않음
- 윈도우 [장치관리자] - [인터럽트 요청(IRQ)] : PIC와 연결되어 하드웨어 인터럽트를 보낼 수 있는 장치들 조회 가능

### DMA 입출력

CPU를 거치지 않고 입출력장치와 메모리가 상호작용할 수 있는 입출력 방식

- **DMA(Direct Memory Access)** : 직접 메모리에 접근할 수 있는 입출력 기능
- DMA 입출력 과정  
  ![image.png](image%2039.png)
  - CPU → DMA 컨트롤러 : 입출력장치의 주소, 수행할 연산 등 정보와 함께 입출력 작업 명령
  - DMA 컨트롤러 : 장치 컨트롤러와 상호작용하며 입출력 작업 수행
    - 필요한 경우 메모리에 접근하여 정보 읽거나 씀
  - DMA 컨트롤러 → CPU : 입출력 작업 끝나면 인터럽트 걸어 작업이 끝났음을 알림
- **✨사이클 스틸링(cycle stealing)** : DMA의 시스템 버스 사용으로 인해 CPU가 시스템 버스 사용을 양보하게 되는 상황
  - 시스템 버스는 동시 사용 불가능
- 입출력 버스 : 입출력장치 컨트롤러의 전용 버스
  - 예시) PCIe 버스 : PCI 입출력 버스의 발전된 형태
    - PCIe 버전에 따라 최대 속도 달라질 수 있음
    - PCIe 버스가 여러 레인을 이용해 정보를 주고받을 수 있음
      - 레인 : PCIe 버스를 통해 정보를 송수신하는 단위

# Q&A
## 1. 사이클 스틸링이란 무엇인가요?
DMA의 시스템 버스 사용으로 인해 CPU가 시스템 버스를 사용하지 못하게 되는 상황입니다.  
시스템 버스는 동시 사용이 불가능하기 때문에 DMA 컨트롤러가 메모리에 직접 접근하기 위해 시스템 버스를 사용하면 CPU는 사용하지 못하게 됩니다.

## 2. 장치 컨트롤러의 기능은 무엇인가요?
장치 컨트롤러는 CPU와 입출력장치 사이의 통신을 중개하면서 정보를 규격화합니다.  
또 입출력장치에 오류가 있는지 검출하며, 버퍼를 활용해 전송률이 다른 장치의 데이터 전송률을 비슷하게 맞춥니다.

## 3. 캐시 메모리는 왜 사용해야 하나요?
캐시 메모리는 CPU의 연산 속도와 메모리 접근 속도의 차이를 줄이며 높은 캐시 적중률은 CPU 성능 향상에 기여할 수 있기 때문입니다.  
CPU가 메모리에 접근하는 속도가 상대적으로 레지스터에 접근하는 속도보다 느리기 때문에 CPU와 메모리 사이에 위치한 캐시 메모리를 사용해 CPU가 사용할 일부 데이터를 예측하여 미리 캐시 메모리로 가지고 옵니다.  
이 때 캐시 메모리는 메모리보다 용량이 작아 참조 지역성의 원리에 의해 CPU가 사용할 거라고 예측된 데이터를 가져오게 되고, 이 데이터가 실제로 사용되어 캐시 적중률이 높으면 해당 데이터에 접근하기 위한 횟수를 줄일 수 있어 CPU의 성능이 향상됩니다.
