# 4. 효율적 쿼리
## 4-1. 서브 쿼리와 조인
- 데이터베이스에 효율적으로 질의하기 위한 4가지 개념
  1. 서브 쿼리
  2. 조인
  3. 뷰
  4. 인덱스

- 복잡한 요청 시 유용한 질의법
  - **서브 쿼리** : SQL 안에 다른 SQL문이 포함된 구조
  - **조인** : 2개의 테이블을 하나로 합치는 것

### (1) 여러 테이블에 질의하기 
- **하나의 SELECT문으로 여러 테이블 레코드를 조회하기**
    ```SQL
    SELECT 테이블 1. 필드 1, 테이블 1. 필드 2, 테이블 2. 필드 3
        FROM 테이블 1, 테이블 2
        WHERE 테이블 1. 필드 1 = 테이블 2. 필드 2;
    ```
    - 테이블1의 필드1 값과 테이블2의 필드2 값이 같은 레코드을 조회할 수 있음

- 예시
    ```SQL
    CREATE TABLE users (
        user_id INT PRIMARY KEY AUTO_INCREMENT,
        username VARCHAR(50) NOT NULL,
        email VARCHAR(100) UNIQUE,
        birthdate DATE,
        registration_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE posts (
        post_id INT PRIMARY KEY AUTO_INCREMENT,
        user_id INT,
        title VARCHAR(50) NOT NULL,
        content VARCHAR(50),
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        FOREIGN KEY (user_id) REFERENCES users(user_id)
    );

    INSERT INTO users (username, email, birthdate) VALUES
        ('kim', 'kimeexample.com', '1990-01-01'),
        ('lee', 'leedexample.com', '1985-05-15'),
        ('park', 'parkeexample.com', '1992-08-22');

    INSERT INTO posts (user_id, title, content) VALUES
        (1, 'One', 'This is the content of the first post.'),
        (1, 'Two', 'This is the content of the second post.'),
        (2, 'Three', 'This is a post by lee.'),
        (3, 'Four', 'This is a post by park.');

    ```

    ```SQL
    SELECT users.username, users.email, posts.title
        FROM users, posts
        WHERE users.user_id = posts.user_id;
    ```

### (2) 서브 쿼리 
- **서브 쿼리** : 내부에 다른 SQL문이 포함되어 있는 SQL 문
  - 공식 문서 정의 : 다른 SQL문 안에 있는 SELECT문
  - 형식 : 서브 쿼리를 소괄호 안에 작성하여 외부 쿼리와 구분 

- 예시 
  - **SELECT문 안에 SELECT문이 포함된 서브 쿼리**
    ```SQL
    SELECT 
        users.username,
        (SELECT COUNT(*)
        FROM posts
        WHERE posts.user_id = users.user_id) AS post_count
    FROM 
        users;

    ```
    ![alt text](<images/SELECT Subquery 예시.png>)
    - 외부 쿼리 
      - users 테이블에서 username과 서브 쿼리 결과를 조회함
    - 서브 쿼리 
      - 괄호 안 SELECT문으로 post_count라고 명칭 
      - `posts.user_id = users.user_id` 조건인 테이블의 레코드 수 조회
    
  <br>
  
  - **DELETE문 안에 SELECT문이 포함된 서브 쿼리**
    ```SQL
    DELETE FROM posts
    WHERE user_id = (
        SELECT user_id
        FROM users
        WHERE email = 'kimeexample.com'
    );

    ```
    - 외부 쿼리 
      - posts 테이블에서 user_id가 서브 쿼리의 결과와 같은 레코드를 삭제
    - 서브 쿼리 
      - users 테이블에서 `email = 'kimeexample.com'`인 레코드의 user_id를 조회

#### 1. INNER JOIN
  - 일반적인 조인으로 `조인`이라고 부를 때 `INNER JOIN`을 의미함
  - 형식
    ```SQL
    SELECT 
        필드
    FROM 
        테이블1
    INNER JOIN 
        테이블2 ON 테이블1.공통필드 = 테이블2.공통필드;

    ```
    - 테이블1과 테이블2의 레코드 중 조인 조건을 모두 만족하는 데이터만을 선택해 결합 => `교집합 연산`과 동일

    <br>

  - 예시 : `customers.id = orders.customer_id`인 레코드만 선택 후 결합하여 조회
    ```SQL
    SELECT 
        customers.name, 
        customers.age, 
        customers.email, 
        orders.id AS order_id, 
        orders.product_id, 
        orders.quantity, 
        orders.amount
    FROM 
        customers
    INNER JOIN 
        orders ON customers.id = orders.customer_id;

    ```
    ![alt text](<images/orders INNER JOIN.png>)
  
  - 예시 : 조인 결과 + WHERE절 => 레코드 필터링하여 조회
    ```SQL
    SELECT 
        customers.name, 
        customers.age, 
        customers.email, 
        orders.id AS order_id, 
        orders.product_id, 
        orders.quantity, 
        orders.amount
    FROM 
        customers
    INNER JOIN 
        orders ON customers.id = orders.customer_id
    WHERE 
        orders.amount >= 5000;

    ```
    ![alt text](<images/orders INNER JOIN + WHERE.png>)

#### 2. OUTER JOIN 
  - **LEFT OUTER JOIN**
    - 형식
        ```SQL
        SELECT 
            필드
        FROM 
            테이블1
            LEFT OUTER JOIN 테이블2 ON 테이블1.공통필드 = 테이블2.공통필드;
        ```
        - **테이블 1의 모든 레코드를 기준으로 테이블2의 레코드를 합침**
        - 만약 `테이블2에 대응되는 레코드`가 없다면 해당 값을 `NULL`로 간주
    
    <br>

    - 예시 : `customers.id = orders.customer_id`인 레코드를  선택한 후 customers 테이블에 orders 테이블 레코드를 합침
        ```SQL
        SELECT 
            customers.name, 
            orders.id AS order_id, 
            orders.product_id, 
            orders.quantity, 
            orders.amount
        FROM 
            customers 
            LEFT OUTER JOIN orders ON customers.id = orders.customer_id;

        ```
        ![alt text](<images/orders LEFT OUTER JOIN.png>)

    <br>

  - **RIGHT OUTER JOIN**
    - 형식
        ```SQL
        SELECT 
            필드
        FROM 
            테이블1
            RIGHT OUTER JOIN 테이블2 ON 테이블1.공통필드 = 테이블2.공통필드;
        ```
        - **테이블 2의 모든 레코드를 기준으로 테이블1의 레코드를 합침**
        - 만약 `테이블1에 대응되는 레코드`가 없다면 해당 값을 `NULL`로 간주

    <br>

    - 예시 : `customers.id = orders.customer_id`인 레코드를  선택한 후 orders 테이블에 customers 테이블 레코드를 합침
        ```SQL
        SELECT 
            customers.name, 
            orders.id AS order_id, 
            orders.product_id, 
            orders.quantity, 
            orders.amount
        FROM 
            customers
        RIGHT OUTER JOIN 
            orders ON customers.id = orders.customer_id;

        ```
        ![alt text](<images/orders RIGHT OUTER JOIN.png>)

  - **FULL OUTER JOIN**
    - 형식
        ```SQL
        SELECT 
            필드
        FROM 테이블1
            LEFT JOIN 테이블2 ON 테이블1.공통필드 = 테이블2.공통필드

        UNION

        SELECT 
            필드
        FROM 테이블1
            RIGHT JOIN 테이블2 ON 테이블1.공통필드 = 테이블2.공통필드;

        ```
        - **두 테이블의 모든 레코드를 선택**
        - 대응되지 않는 모든 레코드를 NULL로 표기
        - 명시적인 별도의 문법이 지원되지 않으나 LEFT, RIGHT OUTER JOIN을 결합(UNION)하여 구현 가능
          - `UNION` : 합집합을 구하는 키워드

    <br>

    - 예시 : customers 테이블과 orders 테이블 각각 LEFT OUTER 조인 , RIGHT OUTER 조인 후 합침
        ```SQL
        SELECT 
            customers.name, 
            orders.id AS order_id, 
            orders.product_id, 
            orders.quantity, 
            orders.amount
        FROM customers
            LEFT OUTER JOIN orders ON customers.id = orders.customer_id

        UNION

        SELECT 
            customers.name, 
            orders.id AS order_id, 
            orders.product_id, 
            orders.quantity, 
            orders.amount
        FROM customers
            RIGHT OUTER JOIN orders ON customers.id = orders.customer_id;

        ```
        ![alt text](<images/FULL OUTER JOIN.png>)
        - orders 테이블에 없는 customers 테이블의 레코드가 NULL 로 채워지고 customers 테이블에 없는 orders 테이블의 레코드가 NULL로 채워짐

## 4-2. 뷰
- **뷰** : SELECT문의 결과로 만들어진 가상 테이블 
  - 테이블 형태로 이루어진 SELECT문을 가상 테이블로 간주

- **뷰의 특징**
  - `쿼리의 단순화, 재사용성`을 높이기 위해 많이 사용됨
    - 복잡한 조건식을 사용한 SQL문을 하나의 뷰로 만들어두면 쉽게 동일한 결과를 얻을 수 있음
  - 특정 사용자에게 테이블의 특정 데이터만 보여줄 때 사용 가능
    - 뷰의 `접근 권한(GRANT)`을 부여할 수 있음
  - 유의점 
    - 조회에는 제한 X
      - `조회 목적`으로 주로 사용
    - `삽입, 수정, 삭제 등은 불가능할 수 있음`
      - 여러 테이블의 결과로 만들어진 경우 삽입, 수정, 삭제 연산이 제약 조건을 어길 수 있음

- 형식
    ```SQL
    CREATE VIEW 뷰 _ 이름 AS SELECT 문 ;
    ```

<br>

- 예시 : `myview`
  - `생성`
    ```SQL
    CREATE VIEW myview AS
    SELECT 
        users.username, 
        users.email, 
        posts.title
    FROM 
        users, 
        posts
    WHERE 
        users.user_id = posts.user_id;

    ```
    - 논리적 테이블처럼 활용 가능
  - `조회`
    ```SQL
    SHOW TABLES;
    ```
    ![alt text](<images/myview 뷰.png>)

<br>

- 참고 : 서브쿼리를 통해서도 가상 테이블을 만들 수 있음 (SELECT 이중 구조)
  ```SQL
  SELECT 
      result.username, 
      result.email, 
      result.title
  FROM 
      (
          SELECT 
              users.username, 
              users.email, 
              posts.title
          FROM 
              users, 
              posts
          WHERE 
              users.user_id = posts.user_id
      ) AS result
  WHERE 
      result.username = 'kim';

  ```
  - 중복되는 쿼리가 많아 번거로움 => `뷰 활용`

## 4-3. 인덱스
### (1) 인덱스
- **인덱스** : **검색 속도 향상**을 목적으로 만드는 하나 이상의 테이블 필드에 대한 자료구조
  - RDBMS의 성능을 향상시키는 대중적인 방법
    - 많은 레코드를 조회하는 작업이 자주 발생하는 RDBMS에서 주로 활용
  - 남용하면 성능에 악영향

<br>

- 예시 : 학생 테이블, 학번 필드 인덱스 생성
    ![alt text](<images/학번 필드 인덱스.png>)
    - 학번 필드 기준으로 정렬된 인덱스 자료 구조
    - B트리 혹은 B트리의 번형 형태로 생성됨

<br>

### (2) 인덱스의 종류
1. 클러스터형 인덱스 (clustered index)
   - 기본 키
   - 기본 키가 없는 경우 NULL, UNIQUE 제약 조건이 있는 필드
2. 세컨더리 인덱스 (secondary index) 또는 논클러스터형 인덱스 (non-clustered index)
   - 클러스터형 인덱스가 아닌 인덱스
   - 테이블 당 여러 개가 존재할 수 있음
   - 클러스터형 인덱스 검색보다 일반적으로 느림
   - 형식
      ```SQL
      -- 세컨더리 인덱스 생성
      CREATE INDEX 인덱스_이름 
      ON 테이블_이름 (필드);

      -- 인덱스 조회
      SHOW INDEX FROM 테이블_이름;

      -- 인덱스 삭제
      DROP INDEX 인덱스_이름 
      FROM 테이블_이름;

      ```

#### 🚫 여기서 잠깐, 인덱스로 사용되는 자료구조 
- 인덱스의 대표적인 자료 구조 : 해시 테이블, B 트리

- 예시 : 제품 번호 = 기본키, 클러스터형 인덱스 생성

  - B 트리 생성
    ![alt text](<images/B 트리.png>)

### (3) 인덱스 부작용 
- 인덱스의 생성 이전에 고려해야 할 기회비용
  - 인덱스의 저장 공간
    - 테이블 당 3개 이하의 인덱스 권고
  - 인덱스의 생성 시간
- 조회 성능은 향상하지만 그 외 작업(삽입, 삭제, 수정)의 성능은 하락될 수 있음
  - 데이터 삽입, 수정, 삭제 시 인덱스를 유지, 갱신하는 추가적인 자원과 연산 필요
- 중복이 많은 경우 중복된 것들을 어쨌든 다 확인해야해서 성능이 떨어질 수 잇음
  
<br>

- 인덱스가 필요한 경우
  - 데이터가 충분히 많은 경우
  - 조회가 빈번히 이루어지는 테이블 필드
    - 특히 자주 조인되거나 WHERE, ORDER BY가 자주 언급되는 필드


## Q&A 
### Q1. INNER JOIN과 OUTER JOIN의 차이를 설명하고, 각각의 사용 예제를 설명해 보세요.
A1. INNER JOIN은 두 테이블에서 공통된 값이 있는 행만 반환합니다. 즉, 조인 조건에 일치하는 경우에만 결과에 포함됩니다. 예를 들어, 사용자 테이블과 주문 테이블이 있다고 가정하면, INNER JOIN은 특정 사용자가 작성한 주문 정보가 모두 일치할 때만 결과에 포함됩니다.

OUTER JOIN은 일치하지 않는 값도 포함시킬 수 있습니다. OUTER JOIN에는 LEFT OUTER JOIN과 RIGHT OUTER JOIN이 있는데, LEFT OUTER JOIN은 왼쪽 테이블의 모든 데이터를 가져오고, 일치하지 않는 경우에는 NULL 값을 반환합니다. RIGHT OUTER JOIN은 오른쪽 테이블의 모든 데이터를 가져오고, 일치하지 않는 경우 NULL 값을 반환합니다.

예를 들어, 사용자 테이블과 주문 테이블이 있을 때 LEFT OUTER JOIN을 사용하면 사용자 정보는 모두 출력되지만, 주문 정보가 없는 사용자는 NULL로 표시됩니다. 반대로 RIGHT OUTER JOIN은 주문 정보는 모두 출력되지만, 사용자 정보가 없으면 NULL이 표시됩니다.

### Q2. 서브쿼리와 조인의 차이를 설명하고, 서브쿼리를 조인으로 대체할 수 있는 상황을 예제를 통해 설명하시오.
A2. 서브쿼리는 쿼리 안에 또 다른 쿼리가 들어가는 형태입니다. 보통 서브쿼리는 SELECT, INSERT, UPDATE, DELETE 문에서 사용되며, 독립적으로 실행된 후 그 결과를 메인 쿼리에서 사용합니다. 예를 들어, 특정 사용자가 작성한 게시글 개수를 구할 때 서브쿼리를 사용하면 "사용자 ID에 해당하는 게시글 개수"를 구한 후 메인 쿼리에서 출력할 수 있습니다.

조인은 여러 테이블을 결합해 하나의 결과 집합을 반환합니다. 예를 들어, 사용자가 작성한 게시글 개수를 구할 때 조인을 사용하면 사용자 테이블과 게시글 테이블을 조인한 후, 사용자별로 게시글 개수를 집계하면 됩니다.

서브쿼리는 직관적이지만 독립적으로 실행되기 때문에 성능이 떨어질 수 있습니다. 반면, 조인은 한 번에 처리되기 때문에 성능이 좋습니다. 따라서 서브쿼리가 성능 저하를 일으킬 경우 조인으로 대체하는 것이 좋습니다.

### Q3. 인덱스의 종류와 장단점에 대해 설명하고, 인덱스를 생성할 때 주의해야 할 점을 설명하시오.
A3. 인덱스는 데이터베이스에서 검색 성능을 높이기 위해 사용됩니다. 인덱스의 종류에는 크게 클러스터형 인덱스와 세컨더리 인덱스가 있습니다.

먼저, 클러스터형 인덱스는 테이블의 물리적 순서를 인덱스 순서에 맞게 저장합니다. 한 테이블에는 하나의 클러스터형 인덱스만 설정할 수 있습니다. 예를 들어, 사용자 테이블의 ID 필드에 클러스터형 인덱스를 설정하면 ID 순서대로 데이터가 저장됩니다. 이렇게 하면 ID 기반 검색이 빨라지게 됩니다.

반면, 세컨더리 인덱스는 클러스터형 인덱스와 별도로 생성됩니다. 검색 성능을 개선할 수 있지만 삽입, 수정, 삭제 성능이 저하될 수 있습니다. 예를 들어, 사용자 테이블의 이메일 필드에 세컨더리 인덱스를 설정하면 이메일을 기준으로 빠르게 검색할 수 있습니다. 하지만 사용자가 이메일을 자주 수정하면 세컨더리 인덱스가 계속 갱신되면서 성능이 저하될 수 있습니다.

인덱스를 설정할 때 주의할 점은 다음과 같습니다.

첫째, 너무 많은 인덱스를 설정하면 쓰기 성능이 저하될 수 있습니다.

둘째, 자주 사용되지 않는 필드에 인덱스를 설정하면 오히려 성능이 떨어질 수 있습니다.

셋째, 자주 수정되는 필드에는 인덱스 설정을 피하는 것이 좋습니다.

결론적으로, 인덱스는 검색 성능을 높이는 데 매우 유용하지만, 너무 많이 설정하면 트랜잭션 성능이 저하될 수 있습니다. 따라서 검색 성능과 트랜잭션 성능의 균형을 잘 맞추는 것이 중요합니다.
