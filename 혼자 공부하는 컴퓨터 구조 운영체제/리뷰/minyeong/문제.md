## 1. 프로세스와 스레드란 무엇인지 설명하고, 멀티 프로세스와 멀티 스레드의 장단점을 각각 설명해주세요.

프로세스는 운영체제로부터 자원을 할당받은 작업의 단위이며, 스레드는 프로세스가 할당 받은 자원을 이용하는 실행 흐름의 단위를 의미합니다.
하나의 프로세스에서 스레드는 코드, 데이터, 힙, 파일을 공유하며 나머지는 각각 할당 받게 됩니다.

멀티 프로세스란 하나의 프로그램을 여러 개의 프로세스로 구성하여 각 프로세스가 하나의 작업을 처리하는 것을 말하는데요, 즉 프로세스는 독립적으로 실행되기 때문에 다른 프로세스에 문제가 발생해도 지장이 적거나 문제가 없다는 장점이 있습니다. 그러나 잦은 문맥 교환으로 인해 오버헤드가 발생할 수 있고, 프로세스 사이에 통신이 어렵다는 단점이 있습니다.
반면, 멀티 스레드란 하나의 프로세스를 어러 개의 스레드로 구성하여 각 스레드가 하나의 작업을 처리하는 것을 말합니다. 따라서 시스템 자원의 효율성이 증가되고 처리 비용이 감소된다는 장점이 있습니다. 그러나 자원 공유로 인한 동기화 문제나 하나의 스레드에 문제가 발생하면 프로세스 전체에 문제가 생길 수 있다는 단점이 있습니다.
 
 ## 2. 이미 프로세스가 CPU를 실행 중인데 다른 프로세스가 급하게 당장 CPU를 사용하길 원하면 어떻게 할 건가요?

(정답 없음 - CPU 스케줄링 중 하나 설명하면 됨)
에이징 기법을 더한 우선순위 스케줄링 방식을 사용하여 가장 우선순위가 높은 프로세스를 CPU에 할당하겠습니다.
우선순위 스케줄링은 선점형 스케줄링인데요, 운영체제가 자원을 이미 사용하고 있는 프로세스로부터 강제로 빼앗아 할당할 수 있는 스케줄링 방식입니다.
우선순위대로 할당하게 되면 우선순위가 낮은 프로세스의 실행이 밀리는 기아현상이 발생하게 되는데 이를 방지하기 위해 오래 대기한 프로세스의 우선순위를 점차 높이는 방식인 에이징 기법을 사용하겠습니다.

| 기타 답안 |  
**선점형 스케줄링**
1. **라운드 로빈 스케줄링**을 사용하여 정해진 시간만큼만 돌아가며 CPU를 할당할 수 있도록 하겠습니다. 이 스케줄링은 한 프로세스의 자원 독점을 막고 골고루 배분한다는 장점이 있지만, 이 타임 슬라이스가 크면 문맥 교환에서 오버헤드가 발생할 수 있고, 작으면 CPU 사용 시간이 긴 프로세스에 의해 상대적으로 사용 시간이 짧은 프로세스들이 오래 기다리는 호위 효과가 발생할 수 있다는 단점이 있습니다.
2. **최소 잔여 시간 우선 스케줄링/SRT 스케줄링**을 사용하여 정해진 시간만큼 CPU를 사용하되, CPU를 사용할 다음 프로세스는 남아있는 작업 시간이 가장 적은 프로세스로 정하겠습니다.
3. **다단계 큐 스케줄링**을 사용하여 우선순위별로 준비 큐를 여러 개 두고 CPU를 할당하겠습니다. 큐별로 시간을 정할 수 있고, 다른 스케줄링 알고리즘을 사용할 수 있기 때문에 효율적이지만 큐 간 프로세스가 이동이 불가하여 기아 현상이 발생할 수 있습니다.
4. **다단계 피드백 큐 스케줄링**을 사용하겠습니다. 프로세스들이 큐 사이를 이동할 수 있기 때문에 새로 준비된 프로세스가 있다면 우선순위가 높은 큐에 삽입되어 일정 시간 동안 실행되고, 끝나지 않으면 다음 우선순위 큐에 삽입되어 실행됩니다. 이 때 CPU를 오래 사용해야 하는 CPU 집중 프로세스들은 우선순위가 점차 낮아질 수 있는데 에이징 기법을 사용하여 기아 현상을 방지하겠습니다.

**비선점형 스케줄링**
1. **선입 선처리 스케줄링/FCFS 스케줄링**을 사용하여 준비 큐에 삽입된 순서대로 CPU를 할당하겠습니다. 비선점형 스케줄링으로 하나의 프로세스가 자원을 사용하고 있다면 종료되거나 스스로 대기 상태에 접어들 때까지 다른 프로세스가 끼어들 수 없어 문맥 교환 과정에서 오버헤드가 적다는 장점이 있습니다. 반면, 모든 프로세스가 골고루 자원을 사용할 수 없고 CPU 사용 시간이 긴 프로세스에 의해 상대적으로 사용 시간이 짧은 프로세스들이 오래 기다리는 호위 효과가 나타날 수 있다는 단점이 있습니다.
2. **최단 작업 우선 스케줄링/SJF스케줄링**을 사용하겠습니다. 준비된 큐에 삽입된 프로세스들 중 CPU 사용 시간의 길이가 가장 짧은 프로세스부터 CPU를 할당하는 방식입니다.
   
## 3. 교착 상태란 무엇이고 해결 방법은 무엇인가요?

교착 상태란 일어나지 않을 사건을 기다리며 진행이 멈춰버리는 현상입니다.  
발생 조건은 네가지로, 첫 째 상호 배제, 한 프로세스가 사용하는 자원을 다른 프로세스가 사용할 수 없을 때, 둘 째 점유와 대기, 자원을 할당받은 상태에서 다른 자원을 할당 받기를 기다리는 상태일 때, 셋 째 비선점, 어떤 프로세스도 다른 프로세스의 자원을 강제로 빼앗지 못할 때, 넷 째 원형 대기, 프로세스들이 원의 형태로 자원을 대기할 때 발생합니다.  
이를 해결하기 위한 방법으로 크게 세 가지가 있는데, 먼저 교착 상태의 발생 조건 중 하나를 충족하지 못하게 하여 예방하거나 안전 상태를 유지할 수 있을 경우에만 자원을 할당하여 회피하는 방법이 있습니다. 마지막으로 교착 상태 발생 여부를 주기적으로 검사하고 교착 상태가 발생하면 선점을 통해 회복 하거나 프로세스를 강제 종료하여 회복하는 방법이 있습니다.

## 4. 운영 체제란 무엇인가요?

운영 체제란 커널 영역에 적재되어 사용자 영역에 적재된 프로그램들에 자원을 할당하고, 올바르게 실행되도록 돕는 프로그램입니다.

## 5. 문맥 교환이란 무엇이고 일어나는 과정을 설명해주세요.

문맥 교환이란 프로세스 간 실행 전환을 의미합니다.  
하나의 프로세스에서 다른 프로세스로 실행 순서가 넘어갈 때는 운영체제에서 프로세스 스케줄러에 의해 인터럽트가 발생됩니다. 프로세스가 실행되는 사용자 모드에서 커널 모드로 전환되어 기존에 실행되었던 프로세스 정보를 PCB에 백업하고 다음에 실행할 프로세스의 PCB로부터 문맥을 복구하게 됩니다. 그 다음 다시 커널모드에서 사용자 모드로 전환하여 프로세스를 실행하게 됩니다.
