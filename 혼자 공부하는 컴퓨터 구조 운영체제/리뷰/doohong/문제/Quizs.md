# 혼자 공부하는 컴퓨터 구조 운영체제 1-15장 복습 Quizs
## Q1. 컴퓨터의 구조와 각 구조들이 하는 역할들에 대해 설명하세요 (1-8장)
A1. 컴퓨터의 구조에는 CPU, 메모리, 보조기억장치, 입출력장치라는 네 가지 핵심 부품이 있습니다. 

그 중 CPU는 중앙처리장치로 메모리에 저장된 명령어를 읽어들이고 읽어들인 명령어를 해석하고 실행하는 부품입니다. CPU는 다음과 같은 구성 요소를 가집니다. 첫번째로, 컴퓨터 내부 계산을 수행하는 `ALU`. 두번째로는 CPU 내부의 임시 저장 장치인 `레지스터`, 세번째로는 제어 신호를 보내 명령어를 해석하고 메모리를 읽거나 쓰는 전기로 된 제어 신호를 보내는 제어 장치가 있습니다.

메모리는 현재 실행되는 프로그램의 명령어와 데이터를 저장하는 부품으로 저장된 데이터가 휘발되며 주소를 통해 원하는 위치로 접근이 가능합니다.

보조기억장치는 자기적인 방식을 이용하는 하드디스크와 전기적인 방식을 이용하는 플래시메모리로 구성됩니다.메모리의 약점을 보완하기 위해 저장 용량이 크고 저장된 내용을 잃지 않습니다.

입출력 장치는 컴퓨터 외부에 연결하여 장치 컨트롤러에서 데이터 버퍼링을 진행하며 컴퓨터 내부와 정보를 교환합니다. 메모리가 CPU를 거쳐 상호작용하며 데이터 입출력이 진행되지만 DMA 입출력의 경우 메모리에 직접 접근하여 입출려갛게 됩니다. 

## Q2. 명령어 처리 과정은 어떻게 되는가? (4장 - 명령어 사이클과 인터럽트)
A2. CPU는 하나의 명령어를 처리하는 과정에 정해진 흐름을 반복하며 명령어 사이클에 따라 명령어를 처리하게 됩니다.

인출 사이클은 메모리에 있는 명령어를 CPU로 가져오는 단계이며, 실행 사이클은 CPU로 가져온 명령어를 실행하는 단계입니다. 실행 사이클에서 제어장치가 명령어 레지스터에 담긴 값을 해석하고 제어 신호를 발생시킵니다. 간접사이클은 유효 주소의 주소를 명시하는 경우 명령어를 실행하기 위해 메모리에 한번 더 접근하기 위해 실행됩니다. 

프로그램 속 각각의 명령어들은 명령어 사이클이 반복되며 실행됩니다.

## Q3. 명령어 파이프라이닝과 슈퍼스칼라를 비교해주세요. (5장-CPU 성능 향상 기법)
A3. 명령어 파이프라이닝은 명령어가 처리되는 단계를 겹치지 않게 병렬적으로 동시에 실행될 수 있도록 처리하는 기법입니다. 

의존적인 두 명령어를 동시에 실행하려고 하면 데이터 의존성에 의해 데이터 위험이 발생할 수 있습니다. 이런 경우 결과를 저장하기 전 다음 명령어를 입력으로 넣어주거나 이전 명령어 값이 저장되기를 기다렸다 진행합니다.

 또한 프로그램 실행 흐름이 바뀌면서 파이프라인에 들어있던 명령어가 필요 없어지는 것과 같은 프로그램 카운터에 갑작스런 변화가 생가면 제어 위험이 생깁니다. 이를 방지하기 위해 분기를 예측하여 그 주소를 인출하는 기술을 사용하거나 분기에 영향을 받지 않는 명령어를 우선 수행합니다.
 
 마지막으로 명령들을 겹쳐 실행하는 경우 다른 명령어가 동시에 CPU 부품을 사용하려고 할 때 구조적인 위험이 발생할 수 있으며 자원을 추가하거나 명령어 처리를 지연해야합니다.

슈퍼 스칼라는 CPU의 내부에 여러개의 명령어 파이프라인을 포함한 구조를 가집니다. 클럭 주기마다 동시에 여러 명령어를 인출하거나 실행할 수 있으며 파이프라인 개수에 비례하여 프로그램 처리 속도가 빨라집니다.

## Q4. 프로세스의 의미와 동작과정을 설명하고 멀티 프로세스와 멀티 스레드의 장단점을 설명해주세요.
A4. 프로세스는 프로그램을 메모리에 적재하고 실행하는 순간 실행되는 프로그램이며 스레드는 프로세스를 구성하는 실행 단위입니다. 

프로세스의 상태를 나타내는 PCB에는 PID와 상태, 레지스터 값, 스케줄링 정보 등이 저장됩니다. 운영체제는 PCB를 통하여 프로세스를 인식하고 관리합니다. 

프로세스 생성 상태에서는 메모리에 프로세스가 적재되며 생성되고 준비 상태로 CPU의 할당을 기다립니다.

준비 상태는 CPU를 할당받아 실행할 수 있지만 차례를 기다리는 상태입니다.

실행 상태는 CPU를 할당 받아 실행 중인 상태로 할당된 일정 시간 동안 CPU를 사용할 수 있으며 시간이 끝나면 타이머 인터럽트가 발생하고 준비 상태가 됩니다. 

실행 도중 입출력 장치를 사용한다면 입출력 작업을 기다리는 상태인 대기 상태가 되기도 합니다. 입출력 작업이 완료되면 다시 준비 상태로 돌아가 CPU 할당을 기다리게 되며 프로제스가 종료되면 PCB와 프로세스가 사용한 메모리를 정리합니다.

프로세스가 대기 상태로 전환되거나 종료되어 다음 프로세스를 실행하는 경우 문맥 교환이 발생하게 됩니다. 문맥 교환이란 기존 프로세스의 PCB에 관련된 정보를 백업하고 대치될 프로세스의 PCB를 읽어 문맥을 복구하는 것을 의미합니다.

## Q5. 임계 구역과 교착 상태가 무엇인가요?
A5. 임계 구역이랑 공유 자원 중 두 개 이상의 프로세스를 동시에 실행하면 문제가 발생하는 자원을 의미합니다. 잘못된 실행으로 임계 구역의 코드를 실행한 경우 레이스 컨디션이 발생합니다. 

상호 배제를 위한 세 가지 원칙을 지켜야 레이스 컨디션이 발생하지 않을 수 있습니다. 한 프로세스가 임계구역에 접근했으면 다른 프로세스는 들어오지 못하게 하는 `상호배제`, 임계구역에 프로세스가 없으면 진입할 수 있어야 하는 `진행`, 프로세스가 임계 구역에 진입하고 싶은 경우 대기 이후에 언제가는 진입할 수 있어야 하는 `유한 대기` 를 뜻합니다.

레이스 컨디션을 막기 위해 프로세스를 동기화하는 기법으로는 뮤텍스락, 세마포, 모니터가 있습니다.

교착 상태란 둘 이상의 프로세스가 한정된 자원을 요청하는 현상으로 공유 자원에 접근하지 못하고 무한 대기 상태에 빠지는 것을 의미합니다.

교착 상태 발생 조건은 다음과 같습니다. 한 프로세스가 자원을 사용하는 동안 다른 프로세스가 사용할 수 없는 `상호배제`, 자원을 할당받은 상태에서 다른 자원을 할당 받기 위해 기다리는 상태인 `점유와 대기`, 자원을 이용하는 프로세스의 작업이 끝나야만 이용할 수 있는 `비선점 자원`, 자원 할당 그래프를 그렸을 때 원형으로 그려지는 `원형 대기`인 상태입니다.

교착 상태를 해결하는 방법은 교착 상태를 예방하거나 회피하거나 검출 후 회복하는 것입니다. 예방하는 것은 교착 상태의 발생 조건들을 예방하는 것이 있지만 온전히 보완하기는 어렵습니다. 교착 상태 회피는 교착 상태가 발생하지 않도록 안전 순서열에 맞춰 자원을 할당하는 방법입니다. 검출 후 회복은 선점을 통해 회복하거나 강제 종료를 하여 회복하는 방법이 있습니다.
